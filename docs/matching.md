# 对账规则

## 输入

标准模型保存来源、账户、业务日期、入账日期、方向、绝对金额（分，字符串）、币种、摘要 / 备注 / 对方、业务编号、文件哈希、工作表、原行号及本地原始字段。PDF 另有页号；转账有组 ID 和转账标志。

来源加账户构成键。随手记只进入用户映射的目标账户，未选中 / 未映射 / 非 CNY / 缺失当前日期口径的记录仍显示。共同观测范围外标为“期间外 / 覆盖不足”，不判定漏记。业务日期不因时区转换偏移。容差 0–31 个日历日。

## 默认日终余额视图

默认结果按单个借记卡 / 支付账户、交易日期从旧到新展示。随手记期初余额由用户提供，三个工作表的收支和转账共同累计；转账两侧各归入自身账户。银行日终余额来自同账户、CNY、日期顺序与逐笔余额链有效的当天最后一笔。日期倒序文件会反向校验。只有一个可确定的结果时才采用；多文件同日重叠、余额不完整或顺序有歧义时需用户核实填写。

只有日终余额精确相等才为正常日，正常日可隐藏，互相抵消的明细差异不再提示。尚未输入期初余额、相关文件解析出错或未确认导出完整性时不判为正常。银行范围内的无流水日可沿用前日已知余额；范围外及微信无余额文件不从净收支推断余额。跨日差额延续会提示。

异常日支出按同日同额分组；唯一非空对方或摘要相同而金额不同的记录提供改金额线索；其余提供补记 / 多记线索，不自动修改或确认。转账单独列出，银行同日同额可能对应随手记转账时供人工核实。收入单独展示，但全部参与余额计算。

以下规则仍用于“信用卡与逐笔核对”页面，信用卡引擎与报告格式未变。

## 匹配顺序

1. 标出范围外记录，验证已有人工组。每条记录只能占用一次。
2. 用户确认两侧交易编号含义一致后，才优先按编号；成功仍须满足账户、CNY、方向、金额、日期约束。
3. 按账户、币种、方向、金额、业务日期严格分组。双侧各一条才自动匹配；同日同额多笔保留全部，标为疑似重复 / 多候选。
4. 剩余记录构建候选。金额、方向相同且在容差内的日期差异进入人工确认。同一非空摘要、同金额同方向且相距不超过 31 天，也会作为超出容差的日期偏差线索，理由中标明容差，不自动确认。
5. 同日、同方向、非空摘要归一化后一致但金额不同，才列为疑似金额不一致。方向候选须同日、同金额、非空摘要一致。金额相近本身不能建立关系。
6. 多候选按连通组展示，不任意抢占。无候选的银行记录为疑似漏记，账本记录为疑似多记，均非确定错误。

严格匹配优先。退款作为独立收入。未知方向转账不推断；已识别随手记转出 / 转入分别核对并注明非消费。只汇总账户收支，不能解释为消费分类统计。

## 人工处理

支持一对一、一对多、多对一，不做多对多或无边界子集搜索。必须同账户、CNY、同方向、合计金额相等，全部记录位于所选期间和共同观测范围，且未被占用。

原记录消失、关键字段变化、映射 / 期间变动或占用冲突会使人工组失效并警告。金额、方向、账户不同不能强行确认；可标记修订并重新导入。备注和人工状态不改变原始差额。

## 文件版本、覆盖和汇总

相同文件 SHA-256 拒绝重复导入。不同文件重叠保留，缺少可靠标识时只提示疑似重复。首末日期仅为观测范围，无法证明中间无缺页，需核实原账单完整性。

新版随手记默认替换旧版。记录 ID 包含来源、文件哈希、表、行及关键字段，内容变化可能使整批 ID 变化；不承诺跨版本继承决策。重新导入清除处理备注，人工匹配再次验证。

上次与本次差异按标准字段多重集合比较。旧差异消失可能是修订、删除、设置或范围改变，不等于确认已解决。

期间 / 每日汇总使用 BigInt，按账户分开。收入、支出差额均为银行减账本；详情及报告的净额差异为银行净额减账本净额。顶部汇总保留所选账户 / 期间内全部 CNY 原始记录（包括覆盖不足部分），筛选区域另外显示筛选笔数和金额。人工标签不改变汇总。

Worker 最多检查 200,000 对候选，超出时要求缩小期间或分账户。总额相等不能代替逐笔匹配。
